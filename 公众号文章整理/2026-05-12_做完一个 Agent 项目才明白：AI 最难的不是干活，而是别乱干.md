## 正文

> TL;DR
>
> 做 Agent 项目，难点不是让 AI 自动干活，而是让它在该动的时候动、该停的时候停。Demo 只要跑通，产品要的是边界、判断和刹车，能按人的判断稳定行动。

前段时间部门做 Agent 黑客松，我做了一个叫 TapCut 的小项目。

简单说，它是一个视频创作工具：用户上传素材、选择音乐，系统根据音乐节奏和用户输入，自动生成一段有卡点感的视频。

项目最后拿了第一，但复盘下来，我最大的感受不是 AI 写代码有多快，而是：

**做 Agent 最难的，不是让它动起来，而是让它别乱动。**

## Demo 跑通了，不代表 Agent 真能用

很多人做 Agent，第一反应是让它更自动。

自动理解需求，自动调用工具，自动完成任务。

但真做起来会发现，自动不等于靠谱。

TapCut 里最典型的问题是节奏判断。

AI 很容易给你一个“看起来完成了”的结果：素材用上了，音乐配上了，画面也切了。

但问题是，它可能没有节奏感。

你让它“更卡点一点”，它可能只是多切几次画面；你让它“别那么乱”，它可能又变得太平。

结果是完成了，但不像那么回事。

这就是 Demo 和产品的差别。

Demo 看的是流程能不能跑通。 产品看的是结果能不能稳定接近人的判断。

## Agent 不是更自由，而是更有边界

我后来意识到，不能只靠一句 Prompt 让 AI 自由发挥。

因为“节奏感”这个词，对人来说能懂，但对 Agent 来说太模糊。

你必须把判断拆细。

什么叫有效卡点？ 什么叫切换太频繁？ 什么情况下应该跟着强拍走？

拆到这个程度，Agent 才有可能接住。

所以训练 Agent，本质上不是训练它听话，而是训练它判断。

它不只是要知道下一步做什么，还要知道什么情况下不能继续做。

如果一开始节奏识别错了，后面生成得越完整，问题反而越大。

因为它不是在修正错误，而是在放大错误。

## 好的 Agent，要有刹车

很多 Agent Demo 看起来厉害，是因为它一直在往前跑。

但产品里的 Agent，不能只知道往前跑。

它还要知道什么时候该停。

节奏识别不确定时，要不要降级？ 用户输入明显不靠谱时，要不要提示重来？ 生成结果明显偏了，要不要回到上一步？

这些东西听起来不像 AI 能力，但它们决定了 Agent 靠不靠谱。

没有刹车的 Agent，就像一个特别勤快但没有判断力的实习生。

它一直做，但不一定做对。

## 能动是 Demo，有分寸才是产品

这次做 TapCut 最大的收获，是我发现 Agent 项目不是简单地“把模型接进产品”。

它真正逼你做的，是把那些原本只存在于脑子里的判断讲清楚。

以前我们说一个视频“节奏不对”，人能理解。

但 Agent 不行。

你不讲清楚，它就只能临场发挥。

而临场发挥，在 Demo 里可能很好看，在产品里就很危险。

所以如果 TapCut 继续往下做，我不会一上来就追求“全自动剪完一条视频”。

我反而会先把边界做清楚：哪些地方可以自动判断，哪些地方要让用户确认，哪些结果必须留修改入口。

Agent 不是越自由越高级。

真正高级的是，它在确定的地方自动执行，在不确定的地方停下来，把选择权还给人。

所以，做 Agent 最难的不是动起来。

而是动得有分寸。

**能动，是 Demo。 能按人的判断动，才是产品。**
