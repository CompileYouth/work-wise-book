## 正文

> TL;DR
>
> 很多人不是不想做 Agent，而是做着做着就退回了传统应用的老路。最常见的原因就三个：还是用功能视角在想问题、把 AI 只用成了流程里的插件、又太容易被一个“看起来像 Agent”的 Demo 误导。

今天部门的黑客松比赛结束了，在二十多位基干参与的情况下，我这次做的 Agent 项目拿了第一。

这个结果当然值得高兴，但对我来说，更有意思的不是名次本身，而是借着这次项目，我又一次验证了一个判断：**真正难的，从来不是把一个带 AI 的应用做出来，而是别让它做着做着，又退回传统应用的老路。**

前两篇已经把一个基本判断讲清楚了：不要只用 vibe coding 堆功能，而应该把应用往 Agent 的方向去做。因为功能不等于 Agent，接了模型也不等于 Agent，自动化多一点同样不等于 Agent。

但真正麻烦的地方，从来不是“道理听不懂”，而是“做着做着就跑偏”。

很多项目一开始的目标其实都挺明确，张口闭口也是 Agent、自动执行、智能协作，听起来方向完全没问题。结果做到后面，页面越来越多，按钮越来越多，流程越来越长，AI 也确实接进去了不少，但最后做出来的，仍然还是一个传统应用，只不过比以前多了一层 AI 外壳。

这件事并不少见。 不是大家不想做 Agent，而是太容易不知不觉做回老路。

我看下来，最常见的原因其实就三个。

## 第一，嘴上说做 Agent，脑子里想的还是“功能视角”

这是最根本的问题。

很多人一上手做产品，第一反应还是老习惯：这里缺个功能，那里补个入口，这个页面再加一个按钮，那条流程再接一个能力。整个思考路径仍然是围绕页面、模块、交互和功能点展开的。

这种方式当然没错，传统应用就是这么做出来的，而且过去很多年都很有效。但问题在于，**Agent 不是从功能列表里长出来的。**

传统应用更关心的是：用户点了什么，我该返回什么。 Agent 应用更关心的是：用户真正想完成什么，我该怎么把这件事往前推进。

这两者看起来只差一点，实际完全不是一个层级。前者是在设计操作，后者是在设计任务完成。

一旦起手式还是“缺什么补什么”，后面哪怕用了再多 AI，最后大概率也只是一个功能越来越多的传统软件。因为它的底层组织方式根本没变，仍然是在做模块拼装，而不是围绕目标组织系统。

所以很多人不是不会做 Agent，而是一开始就还在用做传统应用的脑子做 Agent。方向看起来变了，思维方式其实没变。

## 第二，AI 参与进来了，但只是一个功能插件

这是现在另一种特别常见的情况。

很多产品确实接了 AI，也确实能生成、能分析、能推荐、能回答，看起来很智能。但如果仔细看，会发现 AI 只是被塞进了某个局部环节里。

比如点一个按钮，AI 帮你生成一段内容； 某个步骤卡住了，AI 给你一个建议； 填完一堆信息之后，AI 帮你总结一下。

这些都有价值，但它们更像是“AI 功能”，还不是 Agent。

因为 Agent 的关键，不是 AI 有没有出现在某个环节，而是 **AI 有没有真正接手一段任务。**

它是不是在理解目标。 是不是在推进过程。 是不是在根据中间状态判断下一步该做什么。 是不是在必要的时候主动调起别的能力，而不是永远等用户下一次点击。

如果 AI 只是流程里的一个插件，那整个系统的主导权仍然在固定流程手里。用户还是得自己一步步点，自己一步步推进，AI 只是偶尔出来帮一下。这种产品即便体验有所提升，本质上也还是传统应用逻辑。

所以问题往往不是“没用 AI”，而是“只把 AI 用成了插件”。 AI 参与了，不等于 Agent 出现了。

## 第三，看起来像 Agent 的 Demo 太容易做，结果高估了自己离产品的距离

这一点其实特别容易骗人。

现在做一个看起来很像 Agent 的 Demo，门槛已经很低了。接个模型，写点提示词，串几个步骤，再配一个还不错的界面，很快就能跑出一种“它好像真的在自己做事”的感觉。

这种感觉很容易让人兴奋，也很容易让人误判。

因为 Demo 证明的，只是“它能跑一次”。 但真正的产品，要求的是“它能稳定把事情做成”。

这中间差的东西太多了。

输入不清楚的时候怎么办？ 信息不够的时候怎么办？ 某一步结果不好怎么办？ 任务中途失败了怎么办？ 要不要回退？要不要换路径？要不要让用户介入？

这些东西，才决定它到底是一个能工作的系统，还是一个只能展示效果的样品。

很多项目的问题不在于没做出未来感，而在于太早被未来感说服了自己。 看起来已经有 AI 了，有多步流程了，有自动推进了，就觉得自己已经在做 Agent。实际上只是做出了一个“很像 Agent 的演示版”。

而真正难的部分，往往恰恰是 Demo 里最容易被省略的那些：异常处理、状态衔接、路径切换、结果评估、失败兜底。没有这些，产品就很容易重新退回传统应用的方式，因为固定流程永远比动态处理更容易落地。

## 结尾

所以回到最开始那个问题：为什么很多人嘴上在做 Agent，最后做出来的还是传统应用？

原因往往没那么玄乎。很多时候，不是模型不够强，不是工程做不到，也不是大家不理解 Agent 这个词。真正的问题反而很朴素：

一开始还是从功能出发，不是从目标出发； AI 虽然进来了，但只是插件，不是执行者； 再加上被 Demo 的“像”误导了，以为自己已经离真正的 Agent 很近了。

这三个问题叠在一起，最后就很容易出现一种局面：表面上在做 Agent，底层却还是老软件逻辑。

所以做 Agent 最难的地方，很多时候不是把它做出来，而是你得时刻警惕自己：别一边喊着做下一代应用，一边又不知不觉退回最熟悉的老路。
