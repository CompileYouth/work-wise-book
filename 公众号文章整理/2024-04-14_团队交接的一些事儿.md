## 正文

自从两周前团队调整，我接手团队已经两周了。说实话，这两周我还是稀里糊涂的，有客观原因也有主观原因。今天就简单分析一下，以便下周可以更好地步入正轨。

先分析分析客观的原因。

团队的调整其实从年初就开始了，那个时候主要还是业务的调整，具体说就是将原先以技术栈为维度的管理方式改为以业务为维度的管理方式。

更直白些讲就是，原先部门中的开发人员大体上分为 web 端、PC 客户端、APP 端，管理方式是一个 leader 分管一个技术栈。我所在的团队在 web 方向，所以我们平时只会负责业务在 web 方向上的部分。

而最新的管理方式发生了变化，将技术栈整合到了一起，按照业务方向进行横切。比如我们的业务在 web 方向上原本有 A、B、C 三个模块，APP 端也有 A、B、C 三个模块，PC 客户端也一样，现在我们的团队会负责三端的 A 方向。

背景介绍有点啰嗦，简而言之就是我们一个 web 团队，不仅要负责原先 web 方向的 A 模块，还要负责起其他两端的 A 模块。

再简单点说，就是负责的业务变多了，是原先的三倍。

除了业务调整，团队也发生了调整。

本来是前 leader 接手相关的业务的，但是两周前又发生了团队调整，前 leader 调走负责其他模块，我来接手他的所有工作。

在我接手前 leader 工作的时候，按理说他会跟我交代清楚指责的边界，哪些业务模块我该负责，哪些不用负责，但实际情况是他也没法完全梳理出来，所以交接的也还是一笔糊涂账。

还有个很重要的因素，人力十分紧张，导致我现在疲于应付各种琐碎的事情，无法沉下心来思考真正重要的事。

导致人力紧张的根本原因是我这团队负责的业务量变成了原来的三倍，但人数却缩减成了原先的一半。虽说多少人做多少事，但团队的成员都被两个大需求给占着，但零碎的小事源源不断，暂时不得不由我来帮忙解决。

总结一下接手团队都两周了还有点稀里糊涂的原因。

1. 接手的业务量是原先的三倍，而且大部分是自己不熟悉的部分；

2. 从前 leader 接手时就稀里糊涂，埋下了较大的隐患；

3. 人力紧缺，导致不得不把时间耗在各种零碎的事情上，无暇有效思考。
