# 书稿协作规则

书名统一为《专业之外：从学生到职业人的 21 堂成长课》，简称《专业之外》。

完整写作标准见[写作规范](写作规范.md)。以下为执行入口，具体约定以当前写作规范为准；各章的案例和措辞约定见对应章节工作记录。

## 写作必须遵守

1. 从 0—5 年职场读者的信息需求出发，解释工作中的道理与做法，不写成作者自我复盘。描述职业阶段用“工作前几年”，不用“工作头几年”。
2. 亲历案例保留作者的“我”、参与角色及关键因果。允许按主题加工叙事与情节；背景必须清楚，关键行动发生的条件与信息来源的衔接不能省略，无关枝节删去，正文不插入改编声明或编辑旁白。
3. 案例必须体现本节核心问题，不能为了沿用人物而硬套；没有贴切案例时可以直接论述。从案例提炼一般道理。方法适用范围不受案例人物身份和操作细节限制，也不把单次经验推成普遍规律。
4. 行文顺序按主题和理解需要安排，不固定套用“建议—案例—道理—回到案例”；可穿插解释与示范。案例和道理都讲清即止，不用固定字数、篇幅比例或段落数量凑内容。加粗小标题仅在有助于辨认独立论点时使用，不是每节标配；能顺着因果讲清的内容直接连贯行文，不为分标题拆碎论述。
5. 论述采用向第三方说明事情的语气，避免“你接到任务后”等直接劝导；保留人物对话。同一人物称呼保持连贯。称呼自然，正文避免“承接者”等生硬标签。语气优先参照作者约 500 字的手写短文，先说具体事情再说判断，不用抽象总结和泛化兜底把句子写圆。任务不明确时先向任务分配者确认，已有想法只用于求证。表达直白，中文与英文之间留空格，应用程序写作 APP；研发场景使用作者惯用的“埋点”，必要时解释其含义。不能凭“AI 高频词”标签机械换掉作者惯用表达；减少的是空泛和重复，不给某个词设置全书统一次数。
6. 适当回应案例中的责任问题，不能把协作方的遗漏全部转成对新人的要求，也不展开作者检讨。
7. 先确定整章要解决的问题，再分配各节的论证任务。后一节应接着解决前面尚未解决的问题，不能只靠过渡句串联各自完整的短文；案例切换服务于论证，不强求同一案例贯穿。相邻段落也要检查前段留下什么问题、后段为何接在此处；按本文核心任务分配篇幅，不把经历、道理、内容介绍平均写成互不相干的几段。方法与示范逐项对应，小节之间各有分工。同一案例跨节回退时间或切换假设时，要说清条件，避免已确认与未确认的状态混淆。

8. 标题应以日常表达呈现读者关心的工作困惑，让读者带着问题来读，避免流程指令或论文题目。作者的示例用于理解表达方向，不默认是指定标题。开篇可以用紧贴主题的短场景，同时交代作者位置与读者问题；尽早点题不等于第一句宣布“这本书写给谁”。序言重在作者与读者的联系、写作缘由和阅读预期，正文章节重在具体判断与做法。局部案例放在相应小节，不用章首和章末强行制造贯穿感。

## 每章执行

1. 先读《写作规范》《目录》《目录与原文对应》相关部分、本章记录及核心原文；已有读取结果可复用，出现冲突时回到原文。
2. 在“章节工作记录”中整理任务书、案例依据与必要加工，再写正文。有明确任务时直接推进，不另设非必要审批。
3. 交付前通读实际修改后的全文，检查主谓宾、关联词、指代和时间表达；删段后确认设问与过渡仍有前文依据。同时按写作规范检查读者理解、主题、精简程度、作者角色、责任、方法与示范、情境衔接和小节分工，不以自评分或字数代替核对。去重先看段落作用，区分原地复述与呈现感受、解释原因、回应开头所需的呼应。方法不能只列名称，应说明实际怎样判断和操作。顾虑与边界按本节主题取舍，不为回应评审而机械补齐所有例外；不把“你看着办”或单方记录等同于无限授权。作者感受按原文和解释需要保留，不规定每节一个情绪瞬间。
4. 先核对评审所指的当前文件及作者累计要求。作者明确要求优先于供参考的评审建议，不为采纳新评审恢复已否定的段落或改掉指定术语、视角；作者明确改变要求时按新要求执行。结构稳定时以局部修改为主。通用经验合并进写作规范，只保留当前有效的要求，不另建逐轮修订记录或改动清单；确需长期保留的案例依据和章内特例按需记录，不把例子或局部改法升级为全书模板。
5. 规则更新、编辑自查和作者认可分开记录，不能因沉淀规则或完成自查便将当前全文标为作者已通过。各章历史通过状态不自动延续到后续改稿。
6. 未被明确要求时，不继续撰写其他章节，不自行提交 Git，不改动公众号原文。
