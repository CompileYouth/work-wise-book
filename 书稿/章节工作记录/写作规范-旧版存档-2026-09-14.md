章反馈）：列举现象用开放写法（“有时是……也有……”），不写“常见的意外有几类”这类像把情况穷尽了的句子；不写“先从最常见的说起：……还能做什么？”这类预告下文的过渡句和引导式设问，说完当前内容直接进入下一节；读者默认具备互联网工作背景，“埋点”“MVP”这类行业常用词直接使用不解释，只有当某个机制直接支撑论点时（如 hotfix 跳过完整测试），把机制当事实随叙述带出，不写成“就是……”式定义。生造短语再添反例：“知道一点线索就带一程”。此前 v22 新增两条（第 5 章反馈）：正文不用有时效的说法，如“现在的公司”“最近”，表述要放几年后读仍然成立；跨章提到讲过的事，不写“这件事前面提到过”这类回指（给读者“是不是漏读了”的压力），直接用一两句把必要背景重述出来。此前 v21 补充：不用“框架式引入句”（“有个需求让我把这笔账算得很仔细”这类把事件当主语引出故事的句子），像作者原文一样直接开始讲事（“有一次，……”“前几天，产品经理又给我出了个难题”）；交代背景不依赖行话，讲不清就换大白话或删；枚举用“首先、其次、最后”等常规写法，不造“头一件”；过程细节以对主旨有用为准，支线情节整段删。此前 v20 吸收第 3 ## 核心规则：从样章修订中确立的写作要求

以下规则适用于全书。案例身份、具体业务与段落数量不作为其他章节的固定模板。

1. **为读者解释工作，不写成作者自我复盘。** 每节围绕一个读者需要理解的问题展开。作者的亲历用于说明道理，讲解落到职场中的判断与做法；不围绕作者的反省、道歉或心路历程铺开。
2. **保留作者角色和关键因果。** 作者亲身参与的案例保留“我”及实际角色。加工前先明确谁交代任务、谁执行、哪里产生分歧及其后果，不能把作者换成匿名角色，或删掉决定误解为何发生的关系。尤其要写清关键行动发生在什么条件下：“要求还含糊时就答应下来”不能简化为“接下了任务”，否则会丢掉案例要说明的问题。
3. **案例可以重构，背景必须讲清。** 原日更文章是素材，不是叙事模板。作者已授权调整顺序、节奏、次要角色和情节，具体化任务与规则，补充对话及后续。读者无需读原文，也应一次看懂任务、分歧和后果；“有很多问题”“两个版本有差异”不能代替具体说明。
4. **只留下解释主题所需的背景。** 细节真实发生过，不等于必须写入。删去一项背景若不影响理解，就可以删；删去后若人物行为或因果不再成立，就应保留。优先选能同时交代人物关系、引出问题、支持后续判断的细节；具体不等于多写背景，必要时一句日常对话就够。不要先复述一遍原事，再换人重讲一遍。精简时不能删断必要的动作衔接：出现聊天记录、文件或反馈前，应交代它如何到达当前人物手中；不能让读者自行补全“谁发来、为何看到”。
5. **从具体案例提炼一般道理。** 论述要回到小节主题，不能停留在案例中的某个操作细节。案例人物的身份不自动限定方法的适用人群；同样，也不能把一个团队的制度或单次结果推成普遍规律。
6. **行文顺序服从内容。** 不固定采用“建议—案例—道理—回到案例”的结构，也不规定案例或论述各占几段。可以从经历、问题或判断切入，说明与例子按理解需要穿插。标准是核心职场道理清楚、上下文连贯，读者无需来回寻找线索；不能把某次局部改稿的顺序升级为全书模板。加粗小标题同样按需使用，不能因作者在某节允许或要求使用，就套到后续每一节。
7. **案例和道理都要精练。** 案例交代清楚就转入论述；论述讲清为什么、怎么做及必要边界即可。不能长篇故事后只补一句口号，也不能围绕同一结论反复劝说。相邻段落若只是换个说法强调同一件事，就合并或删除；不为字数预算、段落比例或“讲透”而扩写。精简不等于每段平均缩短：先判断本文最需要讲清哪件事，给它足够篇幅；辅助背景和内容概述可以更短。精简也不能把方法压成几个标签；需要展开时，应补充具体判断、操作或适用条件，而非重复强调。顾虑和边界只在影响当前做法时说明，不为追求滴水不漏加上“也不一定”“不能保证”等兜底段，也不逐一应对所有可能的例外。评审建议要先判断是否帮助本节解释主题；完整性不能压过读者理解和自然行文。
8. **用向第三方说明事情的语气。** 论述以人物、角色或事情本身展开，避免“你接到任务后”“下次你要”等直接劝导。案例中的“我”和对话中的人称正常保留，使用自然称呼，正文避免“承接者”这种生硬标签，可按语境写“接任务的人”“同事”或直接省略主语；不把“你”机械替换成反复出现的角色名。
9. **用直白的话说明动作。** 少用抽象概括、教材式评价和重复措辞。直接说“用自己的话把要做的事讲一遍”，避免“有用的复述需要包含准备采用的做法”；能直接提出做法，就不用“这是值得养成的工作习惯”再评一句。多个动作挤在一句里时，按实际先后拆开；抽象条件难懂时，用当前情境说明。已经说清具体事情，就不要再把它翻译成一层抽象总结。用词取舍以作者习惯和上下文为依据，不凭“AI 高频词”标签批量替换；具体标准见“语言与段落”。对话中换了行动者，应补回主语，不能让读者猜是谁在确认。
10. **能主动改进，不等于独自承担全部责任。** 案例呈现了上级或协作方的遗漏、质问时，应简要交代相应责任，再讲接任务的人可以采取的行动。不能放着质问不回应，直接把改进要求全部压给新人；也不因此恢复长篇作者检讨或责任争论。
11. **方法、示范与小节分工对应。** 论述列出的要点，应在示范中看得到其用法。示范承接不了时，先判断该要点是否属于本节：必要的补进示范，属于后节的移走，不机械扩充例子。同一概念由主要负责的小节讲清，后续在实际使用时沿用名称，不重新定义，也不为了避重换一套叫法。加粗小标题应覆盖其下全部内容，独立要素不能藏在不相干的标题下。标题提出的处境若与案例不同，需要说明方法为何同样适用，不能为扣题擅自把未知经过补写成原文事实。
12. **同一案例跨节使用，时点和条件要明确。** 区分真实经过、改进做法的假设、时间回退和后续分支。前节已确认的事项，后节再讨论尚未确认的情况时，先用自然语言说明时点或条件，避免读者误以为故事连续发生。假设不能被叙述成已经实现的真实结果。
13. **正文不写编辑过程。** 不加“下面这个案例改编自……”“为方便讨论，设定……”等旁白，首次出现也不例外。素材来源、情节加工、事实对照与审稿状态只放在章节工作记录中；新增外部事实、引文、制度与数据仍需依据。
14. **先写成一章，再检查每一节。** 全章围绕一个核心问题推进，明确前一节解决了什么、还留下什么、下一节为什么需要出现。条件分支不伪装成人人都要依次执行的步骤。各节不重复起头、定义和收尾；整合时可以移动段落、收缩案例和调整标题，不能只添加过渡句。相邻段落要有内容上的承接：前段留下什么疑问，后段为什么回答它。若多个段落互换顺序也几乎不影响理解，应检查是否只是在并排列话题。“这也是”“于是”等连接词不能替代这个关系。案例多不必然零散，同一案例贯穿也不必然连贯，判断依据是论证是否持续推进。
15. **标题提出读者关心的问题，章首建立准确预期。** 小节标题让读者认出自己遇到的麻烦，带着问题往下读；用日常会说的话提出困惑，不机械复述流程、堆叠方法名或写成论文题目。作者举例是在说明表达方向，不等于指定最终措辞，不能未经判断直接照用。标题必须与正文实际回答的问题一致；鲜明不等于夸张承诺。开篇要让读者尽早进入问题，但不等于第一句宣布读者定位或中心结论。优先从作者确实接触过、与本文主题紧密相关的动作或场景进入；不为求自然改用泛泛的人生背景。若用案例开篇，案例承担的作用必须与全章组织相符。只服务于某一节的案例放在该节，不靠移到章首、章末再回扣制造贯穿感。
16. **统一排版。** 应用程序写作 APP；中文与英文词或缩写之间留空格，如“使用 AI”“小 Q”“用 Python 生成 Word”。路径、原文链接等需要精确匹配的内容保持原样。

## 一、这本书怎样与读者说话

像一位用工作经历帮新人理解问题的前辈：熟悉事情，有自己的判断，用具体因果说明建议为什么有用。亲历身份让讲述可信，讲解的落点始终是读者面对类似任务时如何判断和行动。作者可以通过自己怎样听到、遇到和理解这些问题来建立可信度，不必先报履历；一句有依据的“有些坑我自己也踩过”，可以说明作者也经历过困惑，不需要铺成长历程或把读者摆在被考核的位置。

语气优先参照作者明确说明为手写的约 500 字短文：事情和来由交代清楚后，直接说判断、做法与原因。2026 年文章可以提供观点，不把其中的概括语和反复强调带进书稿。允许自然的“说实话”“怎么做呢”等表达，但不为模仿而逐节安排口头禅；全书仍遵循第三方阐述的视角。

**忠实于作者的思考方式，按书籍阅读需要重整表达。** 原文中的口头习惯、绝对判断、连载铺垫和传播性标题，分别取舍，不原样复制。

## 二、从原文中提炼出的风格

| 原文中的表现 | 书稿中的写法 | 需要收住的地方 |
| --- | --- | --- |
| 从停水、被评审代码、一次任务交接等小事切入 | 开篇尽早给出人物、要做的事和具体障碍，让读者进入现场 | 不先铺“当今职场”“时代变化”等宏观背景；不为每一节重新开一个故事 |
| 把自己的第一反应、猜测和修正写出来 | 保留“我以为”“回头看”等有内容的判断变化，让读者理解哪里出了偏差 | 不把作者塑造成一开始就看穿所有问题的人；保留对判断有用的真实感受，不设每节一次的配额，不为“温度”虚构戏剧反应 |
| 用白话解释概念，再回到事情上 | 先让读者理解现象，再给概念命名，并用行动说明含义 | 不堆术语，不为简单做法另造模型；同一概念在一章解释一次即可 |
| 顺着因果或步骤拆开问题 | 写清为什么问这句话、为什么查这一步、它改变了哪个判断 | 不只列“提高意识、加强沟通、主动担当”等抽象要求 |
| 预想到读者的犹豫，再作回应 | 在需要处回应“上级没空怎么办”“这样问会不会显得能力差”等真实顾虑 | 不代替读者制造愚蠢反驳，也不每段都设问自答 |
| 偶尔自嘲，承认不耐烦、别扭或判断失误 | 保留适量轻松语气，把幽默落在自己的处境上 | 不用粗话、讽刺新人或嘲笑协作者制造亲近感 |
| 讲完道理会回到可执行的做法 | 让读者得到可提出的问题、可尝试的动作、可比较的选项 | 不把每章都写成操作清单，解释和例子仍需承担论证 |

可复核的语气依据：

- 《我的代码被喷了》里的“别急，且听我狡辩”，紧接着承认没有达成共识就使用自己偏好的规则。可学的是坦诚和自嘲，以及区分方案与行为的问题。
- 《抓住抉择点》写15:30时“不收尾就浑身不舒服”，再交代错误选择怎样影响16:00的会议。细节解释了判断失误，不只是装饰故事。
- 《记一次典型的bug排查经历》先承认没接触过系统，再拆开投放链路、逐步验证。可学的是让读者看见推理过程，成书时同时检查结论是否超出证据。
- 《别独自吃饭，也别总和熟人吃饭》从消息发错人写到约饭，再坦陈自己遇见熟人可能假装没看见。经历与建议之间有个人阻力，读者才理解改变为何不容易。
- 《如何更好的承接任务？》先写复述与难点，再解释方案文档、同步信息各有什么用。方法要带目的，不能只剩动作名。
- 《AI老是差一口气，问题往往出在一开始》用“完成线”串起具体标准与后续返工。保留这种集中论述，压缩同一结论的多轮重述。

本轮短文重读的具体取法（2026-09-10）：

- 《刚入职能很快进入深度工作状态吗？》先写一个月的实际感受，遇到拗口定义马上改用“被人拍肩膀吓一跳”的体验来解释。学习这种把话说具体的做法，不直接搬用对读者的“你”。
- 《估算陌生项目的工作量》先交代新业务陌生、产品第二天要汇报，才讲为什么需要估算以及怎样拆解。学习因果和动作之间的衔接，不让背景凭空跳到结论。
- 《分而治之的思维在沟通上的应用》用具体工作量和具体模块说明问题怎样谈开。示例承担解释任务，不在后面反复用抽象句重述同一道理。
- 《增加自己的透明度》直接写上级的要求和自己的担心；《工作中什么时候该说“不”》讲清重要性、紧急程度和资源的判断。保留判断的直接，不照搬过强的普遍断言。

## 三、语言与段落

1. **选择自然、连续的叙述视角。** 亲历案例保留作者的“我”；解释道理与方法时，默认采用向第三方说明事情的语气，通过具体人物、角色或事情本身展开。避免“你接到任务后”“下次你要”等对读者直接劝导的句式。示范对话中的人称按实际交流关系保留，不把所有“你”机械替换成“职场新人”而造成生硬重复。同一人物沿用已建立的称呼，避免无必要地换成另一种身份标签；如前文介绍“班主任女儿”，后文继续称“班主任女儿”或“她”，不突然改称“那位实习生”。案例人物沿用原文里的称呼，不为避免跨章重名而改名去重；不同章节的重名人物不需要相互区分。不在叙事中介绍角色是怎样编出来的，不额外宣称加工过的细节是本人逐字记下的真实对话。引用外部事实与观点仍保留必要出处。
2. **优先使用具体动词。** 例如“用自己的话把要做的事讲一遍”，比“有用的复述需要包含准备采用的做法”更清楚。解释动作时直接说清做什么，避免层层抽象，也不把复述任务误写成必须先提交做事方案。研发场景沿用作者惯用的“埋点”，不为求通俗改称“数据记录”。读者默认具备互联网工作背景，“埋点”“MVP”这类行业常用词直接使用，不加“就是……”式解释；只有当某个机制直接支撑论点时（如 hotfix 跳过完整测试才有隐患），把机制当事实随叙述带出，不写成定义。不以通俗为由删掉实际检查的对象和标准。作者惯用的“对齐要求”“对‘做完’的定义达成一致”“提交版本”“按测试用例自测”可以保留，密集重复时按意思改写。某章将“对齐”减到两处，不代表全书每章都限两处；“即可”“据此”等也不一律禁用，判断的是整句话是否自然、准确。
3. **段落跟着一个意思走。** 常见段落用两至五句展开，但不机械计数。一句成段可用于必要的转折或停顿，不把整章切成短视频字幕。列表只用于真正并列、顺序或需要比对的信息。加粗小标题是可选手段：几个需要分别展开的论点，若加标题便于查找和理解，可以使用，标题前后留空行；顺着因果或事情发展就能讲清的内容，保持连贯正文。不能因为能概括出几个小点，就每节都设小标题，也不为排版硬凑小点或拆碎论述。
4. **保留口语的自然，减少日更的痕迹。** 可以用“这就有点尴尬了”“到这一步”等自然衔接；删除“昨天讲过”“明天继续”“今天直奔干货”、关注口号和重复自我介绍。短帖合并后重新安排论证，不按原文顺序粘贴。自然语气更依赖看得见的动作和日常表达，如“当场点头答应，回到工位又不知道明天该多做点什么”；不能只给抽象句添上“其实”“慢慢”“我逐渐意识到”，就认为有了作者的声音。
5. **基础语域：平实的书面语，加自然的口语节奏。** 作者的文字用正常的书面词把事情讲清楚、讲具体：说“工作”“任务”“需求”，不把工作叫“活”；因果直接说出来，如“这锅饭直接影响他的收入”，不绕成“这锅饭的结果落在他自己身上”。口语感来自句子的节奏、具体的动作和自然的自问自答，不来自方言词、评书腔和俏皮话。生造的比喻式短语（“拿这个目的一量”“掉进这道缝里”“掂分量”“揣着手在边上看”“知道一点线索就带一程”）比书面腔更假，一律不用；现成的常用表达（“袖手旁观”“心里有数”“既要又要”）可以正常用。检验标准是“正常人会不会这么说”：一句话如果口头不会这么讲、书面也不会这么写，就重写。讲做法必须写明对象、位置和动作，如“把公告贴在电梯里、小区大门口这些人人必经的地方”，不能只给个方向让读者猜。转折和承上启下也用平实说法，不造“还只是老板的一半功夫”“才轮到那件不用人教的事”这类拧着说的句子。引出案例直接开始讲事（“有一次，……”“前几天，产品经理又给我出了个难题”），不用把事件当主语的框架句（“有个需求让我把这笔账算得很仔细”）；枚举用“首先、其次、最后”“第一、第二”等常规写法；交代背景不依赖行话，读者看不懂的说法换成大白话或删掉，行业内有通用叫法的用通用叫法（说“阻塞”，不自造“挡着其他工作”）；双字词不压成单字（“估算会有偏差”不写“估算会偏”）；过程细节以对主旨有用为准，没用的支线整段删；案例背景只保留与本节主题相关的信息。不用有时效的说法（“现在的公司”），表述要放几年后读仍然成立；跨章提到讲过的事，不写“前面提到过”，也不写“前面讲 X 时说过”这类指路句，直接把事情、做法或必要背景简短说出来；正文不自指章节（“这一章”“上一节”）；同一章内部的就近回指可用内容指代（“前面说的记录和抉择点”）。列举现象用开放写法（“有时是……有时是……也有……”），不写“常见的意外有几类”这类像穷尽分类的句子；不写“先从最常见的说起”这类预告下文的过渡句和引导式设问，说完当前内容直接进入下一节。
6. **避免反复强调和句式整齐。** 不连续使用“真正的……”“不是……而是……”、三连排比或结尾金句。确有必要的区别直接说清；同一结论第二次出现时，应带来新条件、新证据或新行动。去重既看相邻句，也看跨节的提醒：同一句“要问清楚”或“发过消息不等于同意”，不能换个说法反复出现。必要的概念复用不算重复论述。同一主题用于呈现读者感受、解释原因或回应开头时，也可能各有作用；先看每处在本文中做什么，再决定去留。换词重说同一结论应删，承担不同作用的呼应可以保留。
7. **观点直接，适用范围具体。** 用清楚的建议表达立场；限制条件写在实际会影响选择的位置。不用“可能、或许、一定程度上”把每句磨平，也不把单个团队经验扩成所有职场的规则。
8. **统一中英文排版与标点。** 应用程序写作 APP，不写 App；中文与相邻的英文词或缩写之间留空格，如“使用 AI”“小 Q”“用 Python 生成 Word”。文件路径和原文链接保持原样。正文不使用破折号“——”：解释和列举用冒号，补充说明用逗号或“比如”，另起一层意思就断句；专有名词内的连字符不在此列。
9. **结尾落到当前问题。** 可以给出下一次接任务时的一句提问，或回到开篇尚未解决的障碍。不要求每节小结，不重复全章摘要，不突然拔高到人生哲学。章尾若需要收束，用一两句回到本章尚在讨论的问题即可，不强行召回只属于某节的人物。
10. **口语化不能牺牲句子完整。** 检查谁在做什么、动词后有没有必要的对象、指代能否就近找到、关联词是否搭配。人物交替发言时补回主语；时间状语不要叠加；并列检查项用相同的语法层次。不能把两个意思挤成“遇到过一件事跑来咨询我”，也不能把“所有什么”省成“照搬了海外版所有”。
11. **过渡必须接得上实际前文。** 设问前先有问题或概念，不凭空问“‘保质’又是什么意思”；“这时”“这种情况”“再确认一句”要有明确的时间、指代或行动者。删改后读前后整段，不能只看替换后的单句是否顺口。少写“有些返工就从这里开始”这类不增加信息的引导句，能直接讲事情就直接讲。新论点或新概念（如“职场不欢迎惊喜”“求援”）落段前，检查它的直接前文是否产生了引出它的需要；没有就先补一步铺垫，或换个进入方式。
12. **概括句、对照句和原则命名写完后单独回验。** 把这句话概括的对象列出来，逐一核对性质是否相符：案例里停需求的理由是优先级高，就不能写成“工期紧”；转交出去的事，不能贴“事情到我为止”的标签。原则的字面义要与给它的定义一致，概念在案例讲完后自然引出（先讲现象，再给名字），不先贴标签再解释。对照句（“反过来的情况是……”）两边必须真的构成对照。套不上就改结构或换说法，不写“严格说轮不到”“不完全算”这类自我拆台的补丁句。

**语言违禁模式速查**（交稿前按类过一遍，不是只查曾被点名的词）：

- 生造的比喻式短语：“拿这个目的一量”“掉进这道缝里”“知道一点线索就带一程”“线断在自己手里”。自造短语默认删除，除非确认现成表达确实没有。
- 隐喻贯穿论述：一个比喻（如“线/断”）反复用来承担论证，全部换成直说。
- 挂字句与单字压缩：“断在‘我不会’上”“估算会偏”“把参与的人理一遍”“也没有理清楚”（应写“梳理”）“各家出什么”“表格立起来”（应写“建好”）“搭流程”（应写“搭建”）“汇成一页”（应写“汇总成”）“边界也要认”（应写“尊重”），写成完整句子和双字词。名词、形容词同样会被压缩：“会一个接一个”“报的课”（应写“会议”“课程”），“节奏松了不少”“事情不急”“正愁没人做”（应写“宽松”“不紧急”“正发愁”）。再添“拿那天的事来套”（套→套用，应写“拿情绪 ABC 对照那天的事”）。此类问题已五次重犯：交稿前必须把全文的动词、名词、形容词各单独过一遍，动作动词、判断类动词（认、算、看、套）都在内，凡单字都检查是否为双字词的压缩；带方向补语的复合词（漏掉、溜走、占满、闲下来）、无双字原形的词（水、事、人、累）和行业通用说法（修 bug）可保留。整章重写或较大修改后必须重新扫描，不得沿用上一版的扫描结果。
- 抽象名词概括与位移句：“落点在事情上”“就看它最后落在哪里”“下一步就从他身上转到了我身上”——用“落点”这类抽象词概括具体事情，或把责任、状态的变化写成抽象位移，改成直接说人和事：“做完之后参与的每个人都省事”“想清楚这个问题成了我欠他的事”。
- 引语缺上下文：人物原话出现前，先交代他为什么这么说（处境、跟事情的关系）；一句引语解释不了自己，读者就会觉得莫名其妙。背景带不出来时改为转述。
- 拧着说的句子：“还只是老板的一半功夫”“才轮到那件不用人教的事”。
- 定义腔与金句：“就是……”式术语解释、结尾拔高、三连排比。
- 机灵断语与自造警句：“把复盘用小了”“记得太窄”这类拿大小宽窄轻重下俏皮判断的压缩句，以及“吃一次亏才能防住一类亏”式自造对仗，一律拆开平实地说；现成俗语成语不在此列。
- 例子空降：假设例、生活例出场前先交代这类事本身是什么，再讲它说明的道理；“被‘快递丢失理赔’骗过一次的人”这样凭空进入会让读者发懵。
- 电报式残句：“先怀疑发送”“再看问卷统计”，谓语宾语砍到只剩两三个字；写完整的句子：“我最先怀疑的是发送环节出了问题。”
- 抽象总结句领段：“追到不同的深度，能改的东西也不同”，把下文先抽象预支一遍；删掉，直接从具体的事写起。
- 跨小节断裂：同一案例跨节时，新节开头用内容回指接住上一节结束的位置，不直接跳回案例中段。
- 穷尽式列举与预告式过渡：“常见的意外有几类”“先从最常见的说起”。
- 框架式引入句：“有个需求让我把这笔账算得很仔细”，直接开始讲事。
- 章节自指与回指压力：“这一章”“上一节”“前面提到过”“前面讲 X 时说过”，跨章内容直接把事情说出来，不指路；同章内就近回指可用。结构预告是它的变体：“本章前三节讲：……后两节讲：……”这类开篇报大纲的句子一律不写，交代全章范围就直接说事情。
- 读者定位句起头：“刚工作的人多半……”“不少刚工作的人觉得……”连续用作章节开头；开篇直接进入场景或事情，相邻章节开头句式错开。
- 时效表述：“现在的公司”“最近几年”，放几年后读要仍然成立。
- 伪口语：把工作叫“活”、方言词、评书腔。
- 口语词落笔：“头半年”“头一步”“啥”“压根”“搞得”“收工”“翻篇”“调头”“闷头”“出毛病”“交学费”“拿得出手”“心里有底”“记几笔”“翻翻”“挨个”“拉上”“一通”。正文是平实的书面语：前半年、第一步、什么、根本、做得、结束、放下。逐句问“这个词会出现在正式出版的书里吗”，疑似口语一律换书面表达；口语检验（v35/v40）只用来发现不自然的搭配，不是把正文写成口语。
- 回改作者手动修改：作者在正文里手改过的措辞等同规范条文，重写前先通读当前文件，与自己上一版不同的措辞按作者改动原样保留。
- 空转铺垫语：“真正坐下来复盘，第一步是还原”“说到这里”“这时候再看”，不承载信息的铺垫删掉，直接写“复盘的第一步是还原”。
- 比喻动词渗入叙述：围棋比喻里的“摆”跑进正文动作（“把事情按原样重新摆出来”）；实际动作用直白动词（写下来、记录、核对），引入比喻后检查后文动词。
- 过程实录：案例把每一步操作全部写出（第 18 章 §2 六个环节逐一如何验证）；只留支撑论点的关键步骤，每步问“删掉论点还成立吗”，成立就删。
- 排版不一致：小节标题全书统一“## 1. ”阿拉伯数字加点；新章动笔前对照已有章节核对格式。
- 主旨×AI 结合段：在非 AI 主题章节里单独写“本章内容如何配合 AI”的小节或段落（原 18.5、第 21 章 §2 的 AI 段）；顺带提到 AI 的句子不算违规，禁止全书扫荡删除。
- 改错章节：作者指出的问题在第 18 章，却去改第 17 章；处理反馈前先确认问题所在章节，只改该章。
- 标签句起手：先概括归类再解释——“X 就是这样：”“性质是一样的：”“是另一种消耗”“第一步是……”“还有一类麻烦是……”；改成直接讲事实，结论放在事实后面。
- 语境不称的挪用词：“功课”“专利”这类常用词放进工作场景显得别扭；不是生造词也要逐个过“正常人会不会这么说”。

## 四、从案例到方法

主案例应至少让读者理解：当时要做什么、掌握了什么信息、作出了什么判断、采取了什么行动、出现了什么结果或留下了什么问题。不必为凑齐这几项扩写无关背景。

先判断案例是否真正体现本节核心问题，再决定是否使用。讲任务难点，案例就应呈现具体难在何处，不能用缺少账号等准备条件替代任务本身的复杂性；不因人物已经出现就勉强沿用。找不到贴切案例时，可以另选或加工情境，也可以直接论述，不要求每节都有故事。

一章通常选一至两个主案例，允许同一案例贯穿数节，但不以案例数量或贯穿形式限制选材。案例与分析可以按当前问题穿插安排；后续小节推进问题，不重新复述背景。短例用于补足跨岗位适用性或说明边界。

用户已授权围绕既有案例自由补充后续、限制和对话。按照以下方式使用：

| 材料类型 | 可怎样处理 | 写作处理 |
| --- | --- | --- |
| 原文记载的经历 | 提取对主题有用的事实；重排顺序，删去无关支线 | 以真实经历叙述的内容有原文依据；需要实质修改情节时，整体转成改编案例 |
| 根据原案例重构的情境 | 可修改情节、合并角色、具体化任务与规则、重写对话及后续，形成独立完整的故事 | 直接叙事；来源与加工内容记入编辑记录，不在正文逐案说明，不先展示原故事再换人重讲 |
| 假设性的改进办法 | 演示另一种问法、不同选择及可能出现的分支 | 使用“可以这样问”“如果对方回答……”等表达，不伪装成原事件真实结局 |
| 事实、引文与效果数据 | 原文能支持则使用；必要的新外部事实另行核实 | 不为加强观点编造数据、名人原话、制度或研究结论 |

改稿删去某项情节后，工作记录应标为历史设定，不再让旧方案看起来仍是当前正文的依据。

编辑工作记录中简记哪些是原文事实、哪些是新增设定即可，不要求作者补齐每一个细节，也不因允许合理假设的问题中断写作。补充情境用于解释方法，不能再拿其人为安排的好结局证明方法普遍有效。示范中的对方配合，不代表现实中必然配合；确需说明限制时，讲清它会怎样改变做法，不另加一段空泛的“不能保证”。涉及权限或资源时，也不能把单方发出的消息写成双方已经同意。

对旧文中的强判断保留具体问题，重新检查论证与措辞。涉及作者重要立场的变化，记录在章节工作文件中供作者审阅；不能悄悄把编辑新增的观点称为作者已经长期坚持的信念。

## 五、表达对照

下面是编辑示例，不是原文摘录。用来说明判断标准，不作为所有章节的固定句式。

**空泛要求 → 具体动作及其作用**

**刻意升华 → 回到场景**

| --- | --- | --- |
| “实习时遇到过这样一件事跑来咨询我”，后文又写“随后来问我” | 引入句只保留“实习时遇到过这样一件事”，求助动作留给后文 | 修语病的同时去掉重复，不机械补一个逗号就结束 |

序言的职责是建立作者与读者的联系，讲清写书缘由和阅读预期；正文章节则要把具体问题、判断和做法讲透。二者不套用同一套组织方式。样本中的概括语、对比句和省略号不自动变成全书惯用句，更不把“一对一开场—导师—写书”固化为模板。

## 六、统一的按章写作流程

### 开写前

读取本规范、最新目录、本章映射及关联原文；读取涉及同一概念或案例的已写章节和对应记录。标题列表、历史摘要和AI总结不能代替本章核心原文。已读记录用于避免重复劳动，事实有冲突时回到原文。

建立本章工作记录，先说明本文是序言、论述章节还是工具附录，以及它必须替读者完成什么；再写明读者问题、读者动机（读者为什么愿意照着做，好处由哪一节用什么论据讲清）、阅读后的行动、核心观点、各节递进关系、主案例与适用边界。映射列出的素材是清单不是指令：是否采用、用哪一部分，按本章读者需要判断；想因规避说教等顾虑删去某个论点时，先尝试平实改写，确要删除在骨架阶段说明理由请作者确认。把必要的新增设定列出，随后直接写作；已有明确任务与合理假设时，不新增设计审批或逐节确认环节。

骨架给作者过目后、动笔前，默认先用严格审稿人视角自评一轮并落实调整，不需作者每次要求（作者 2026-09-13 定为默认流程）。

骨架定稿前做一次维度检查：为每一节写一句读者处境，看各节是否回答同一层面的问题、处在同一叙述视角上（第 6 章教训：“我遇到麻烦怎么办”与“别让自己成为别人的麻烦”不是一个维度，“事情到我为止”混排在被卡序列里被作者两次指出位置不对）。维度不同的内容，要么调整全章主旨把它安顿进新脉络，要么在文中挑明它与其他节的差别；并列分类里性质不同的项（四类求援里“缺建议”是主动加分项，不是补不上的缺口）不能用同一句落点句一概而论。

### 起草与改稿

按章完成一个连贯版本。内部可以分节起草，但须通读合并，检查称呼、事实、时间、观点与过渡。普通章以6000—8000字为参考，清楚讲完时可更短；不为字数增设故事或反复解释。重点章与全书预算遵循《目录与原文对应》。

先检查读者能否看懂任务、冲突与方法，再核对原文依据、改编处理和论证，最后调整语言，再从头通读修改后的全文。逐句检查主谓宾、修饰关系、关联词和指代，段落检查因果、时点与重复；每次删段后重新检查设问、过渡和结尾是否仍有前文依据。不能以原文链接齐全、人物时间对应、字数达标代替阅读质量检查。不要在案例或核心观点还要改时反复打磨句子。

### 交付前必须检查

先做专项扫描，再做整体通读，二者不能互相替代。专项扫描按类逐项过：全文动词逐个检查是否为双字词的压缩；每段首句检查是否“先概括贴标签再解释”；含数量词、分类词的句子检查是否封闭式列举；比喻词和挪用词检查语境是否相称。通读负责连贯、因果与阅读体验。

| 检查项 | 完成条件 |
| --- | --- |
| 场景清楚 | 能说出任务、关键行动发生的条件及后果；人物如何得到聊天记录、文件等信息有必要交代，没有省掉中间动作 |
| 叙事经济 | 每个人物和背景都影响理解；没有原事加换名演练的双重铺垫；删掉一段若不损失信息，就删掉或合并 |
| 原文与新增内容 | 素材依据与加工内容记入工作记录；正文没有逐案改编说明；不把加工的结局当成实际效果数据 |
| 本文任务与篇幅 | 序言重点解释写作缘由与阅读预期，正文章节讲清判断和做法；核心问题有足够篇幅，辅助内容没有喧宾夺主，没有按话题平均分段 |
| 方法边界 | 只保留影响本节做法的具体限制，不为说圆满加泛化兜底；不以假想成功证明必然有效，不把记录当授权 |
| 作者语气 | 论述采用向第三方说明事情的语气，案例保留作者角色，人物称呼一致；动作直白，没有直接训导、教材腔和重复句；用词是平实书面语，没有把工作说成“活”等伪口语，没有生造的比喻式短语，每句经得起“正常人会不会这么说”的检验 |
| 句子与上下文 | 主谓宾和必要修饰完整，关联词搭配正确；指代、时间及发言者清楚；设问有前文依据，删改没有造成新的断裂 |
| 责任回应 | 案例中的协作方遗漏或质问得到必要回应；接任务的人没有被要求独自承担全部责任 |
| 方法与示范 | 方法有具体判断和做法，必要要点能在示范中落地；明显的小点可用加粗标题分层，不只列名称，也不机械套段落结构 |
| 情境衔接 | 同一案例跨节的时间与条件清楚；回到尚未确认的阶段时有自然提示，假设与实际经过可区分 |
| 整篇连贯 | 开篇场景直接关联主题；相邻段落及各节持续推进问题，能说明为何在此转入下段；呼应各有作用，不靠换开头或添加连接词掩盖话题并列 |
| 跨章分工 | 不重复完整案例；本章只讲其负责的问题，必要内容简短回引 |
| 累计要求 | 新改法没有覆盖作者已明确的视角、术语和角色；没有恢复被否定的段落、固定句式或过度兜底；必要概念复用与重复说理已区分 |
| 文件与状态 | 原文链接可用；正文与工作记录分开；首稿、自查完成、作者认可三个状态分别标明 |

有事实失真或关键逻辑缺口就修改，不用语言分数抵消。自查记录列具体问题及处理，不写“风格匹配95分”等无法验证的数字。AI自查不能替代作者对语气、立场和阅读体验的判断。

### 接收反馈

先读当前文件，确认评审针对的句子仍然存在，再结合作者累计要求取舍。按结构与主题、案例与方法、句子与表达的顺序解决问题；结构已获认可、反馈集中在语句时，只作必要局部修改，不借机重写整章。

- 作者明确指令优先于供参考的评审建议。评审若要求恢复刚删掉的兜底段、改掉已指定的术语，或改成第二人称劝导，先检查冲突，不照单替换。若作者后来明确改变要求，则按新要求更新。
- 区分三类内容：全书通用经验写入本规范；人物、业务情节及章节分工写入本章约定；被否定的版本、修改过程和不采纳理由留在历史记录。一般规则能合并就合并，不为每轮评审再加一组同义要求，也不把一次示例扩成全书模板。
- 修改后核对作者已明确的角色、术语、视角、案例因果和章节边界。正文情节删除，记录中标为历史设定；标题或章节分工改变，同步目录与映射；纯语句修订不必改动无关文件。

记录“原表达—改后表达—理由”，区分作者反馈、外部评审与 AI 自查。通用要求第一次明确就沉淀，不等再次出错。规则更新、编辑自查完成与作者认可分别记录；作者明确认可后，才能标为可复用样章。
