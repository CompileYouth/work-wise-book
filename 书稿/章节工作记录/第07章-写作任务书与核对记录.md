# 第7章 写作任务书与核对记录

状态：第五稿完成（2026-09-13），第四轮反馈（AI 味表述清理）落实，待作者审阅。

## 一、任务书

**本章职责**：第二篇收尾章。第 4—6 章讲把一件事做成的各个环节，本章讲贯穿所有环节的另一面：让交给你事情的人始终放心。落点是“靠谱”的口碑怎么攒出来。

**读者问题**：接了事闷头做，别人不问就不说；估时间脱口而出，到期兑现不了；交付只说“做完了”，问题留给对方发现；休假前一交了之，接手的人寸步难行。

**读完后的行动**：接到事回应、结束时把结论送回去；按事情重要程度主动同步进度、阻塞与下一步；估算带风险余量、兑现从高、变化即重谈；交付前按标准自查并说明实际结果与遗留；休假调岗提前告知、不进新协作、交接到接手的人能继续做。

**核心观点**：“凡事有交代，件件有着落，事事有回音。”别人愿意把事交给你，是因为交到你手里之后，他不用再操这份心。

**各节递进**（分三组，不是纯时间线；章首不作枚举预告）：§1—§2 让人看得到（信息层面：两头有回应有交代，中间过程可见）→ §3—§4 说到做到（承诺层面：估算与兑现，交付与验收）→ §5 人不在事情也不断（极端检验）。章首用作者实习抄便笺的亲历立主线；章尾按“回应、看得见、说到做到、交得清楚、人不在事不断”收拢，回扣便笺，不给下一篇留口。

**维度检查（v25 新流程）**：五节均处于“合作方视角下你是否让人放心”的同一维度，无混排项。

### 第一轮（2026-09-13，首稿语言整体否决，全章重写）

作者意见两条：①案例人物不要为跨章重名改称，尊重原文称呼（小 K 改回小 L，小 D 改回小 M）——已沉淀进规范 v26；②骨架没问题，但语言仍有大量 AI 味和单字压缩，全部重写。

重写时清理的问题（骨架、案例、段落结构不动，逐句重写）：

- 单字压缩：“做事稳”→“做事沉稳”；“核过标准”“一项一项核过”→“核对完标准”“一项一项核对过去”；“交代清”→“交代清楚”；“估工期”→“估算工期”；“同步得多勤”→“同步的频率，要看事情有多重要”；“遗留不丢人”→“有遗留事项不丢人”；“前端的清完了”→“前端的解决完了”；“还挂着一串没解决的”→“还有一长串没有解决”。
- 对仗金句：“同样一个问题，自己查出来是把关，别人查出来就是纰漏”→“自己检查出来，改掉就好了；让别人发现，就成了自己工作里的纰漏”；“攒的是一句话的信用：他说几天，就是几天”→“时间一长，对方就会知道，这个人报的时间是仔细算过的，说几天就是几天”；“牵头的人，验收的就不再是‘我的部分’，而是‘这件事’。角色放大了，交代的范围也要跟着放大”→“牵头负责的人，要验收的是整个需求，不只是自己做的那一部分”；章尾“口碑攒起来很慢……败掉却很快……折掉一大截”对仗段删除。
- 隐喻与生造：“结论躺在群里”→“结论发在群里”；“给每个协作方留了一个空位”→“你负责的那部分只能停在那里等你回来”；“信任是处出来的，不是自带的”→“信任是在一件件事情里慢慢建立起来的”；“脑子里过的是一切顺利的版本”→“脑子里想的全是顺利的情形”；“把状态摆出来”→“主动汇报”；“隔着一道验收”→“中间还差一步验收”；“协作像齿轮，一个咬着一个”→按原文写“就像咬合的齿轮，少了一个，整台机器就要停摆”；章尾“长在了自己身上”→“就真的做到了”。
- 语病与主语：“看了看，觉得不难”补主语“开发的同学”；“被顶上的人”→“被抓来顶替的人”；“出手”→“出面”；“两头受累”→“两边都受累”（避免与 §1“先看两头”撞词）。
- 交接段逻辑理顺：先立“交接的内容一定要自己核实过，不能凭印象”，再进小 M 案例，归因“不是有意隐瞒，而是自己都没核实过就交了出去”。

### 第二轮（2026-09-13，叙事逻辑与人物交代，整篇重写）

作者意见三条：①§1 的例子糊里糊涂；②整体文字已是平实书面语，但有些地方逻辑差、事情交代不清，如 L 哥没有介绍就突然出现；③§5 “人不在了”听起来渗人。

处理：

1. §1 登录案例重写，补齐责任链：先交代团队负责公共登录模块、别的业务接入使用的背景；补回“一星期前登录才出过一次问题、两个人排查了一天”（原文事实，首稿为省篇幅删掉，导致“又出问题”和作者为什么在意都没了着落）；明确小 L 的角色是“代表我们组跟进这个问题”，这样“结论该由他带回来”才成立；结尾点明逻辑“事情的开头他带到了我面前，事情的结论却没有带回来”。
2. §4 的 L 哥补介绍：“组里的 L 哥牵头一个大需求，前端、客户端、后端都有改动，我也深度参与其中”——同时补上“三端都有改动”的背景，后文“所有端加在一起的 bug 解决率”才有着落。
3. §5 “人不在了”改为“谁都有要离开一阵子的时候——休个长假，调去别的团队，或者离职”；章尾对应处改为“离开前把手里的事情安排妥当”。齿轮段补全因果：测试到了约好的提测时间“发现需求还没做完，人也联系不上”（原文事实，上稿只写了一半）。
4. 编辑自查一并修正：全篇论述里的“你”改为第三方视角（“交给你事情的人”→“交办事情的人”；“全看你说不说”→“只能靠做事的人自己说”；“你休假了……找不到你”→“有人临时休假……找不到人”；“绕开你”→“避开这段时间”；章尾“在你不在场的时候”→“别人背后提起自己时”），与前几章“向第三方说明事情”的口吻一致；§2 H 哥段与信任段的衔接补上（“H 哥也许觉得，自己资历摆在这里，上级应该放心才对”）；§2 任务表交代来源（“先把我们负责的工作拆成按天的任务，列进表里”，不再写没有来历的“任务本来就拆好了”）；§2 双份简报补理由（“我们是过去支援的，项目本身还有一位技术负责人”）；“不要再进入新的协作”改为“不要再接新的工作”。

### 第四轮（2026-09-13，AI 味表述清理）

作者指出三处，编辑按同一标准通篇再清理六处：

1. （作者）“事情的开头他带到了我面前，事情的结论却没有带回来”对仗隐喻 → “问题是他早上报给我的，结论却要我自己去群里翻”。
2. （作者）“这件事就算在他手里走完了” → “这件事才算有始有终”（顺带扣回章题）。
3. （作者）“程序员有个通病”不礼貌 → 按原文语气改“我们程序员有个特点，说是优点，也是缺点：乐观”（自嘲口吻，原文即“优点同时又是缺点”）。
4. “从那一声‘出问题了’之后”属“动词＋引语”压缩挂字句 → “可早上说完那一句之后，他就再没跟我提过这件事”。
5. 章首“能力强不强……靠谱不靠谱……”对仗过齐 → “一个人能力强不强，要等到合适的机会才看得出来；靠不靠谱，不用等什么机会，每件小事里都看得见”。
6. “把东西做到能做到的最好”叠字别扭 → “在说好的时间里尽量把东西做好”。
7. “把自己的延误变成所有人的被动”生硬 → “自己延误了，让所有人跟着被动”。
8. “自己查出来是把关，让别人发现就成了纰漏”残余对仗 → “自己检查出来，改掉就好；让测试或者验收的人发现，那就是自己的工作没做到位”。
9. 章尾“别人背后提起自己时说的是”指代绕 → “别人在背后说起一句‘这事交给他，放心’”。
